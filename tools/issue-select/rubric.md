# Rubric: is this a good first issue?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| maintainer-alive | Read the "last 5 default-branch commits," including dates and author names, and the "maintainer first-response sample" under Repo facts. Also read the issue Comments section for comments whose author_association is Owner, Member, or Collaborator. | Pass if at least one of these is true: (1) at least one non-bot author made a default-branch commit within 90 days of the bundle capture date in eval mode or today's date in live mode; (2) the maintainer first-response sample contains at least one Owner, Member, or Collaborator response made within 30 days of the issue opening; or (3) an Owner, Member, or Collaborator commented in this issue within the last 90 days. A bot commit alone does not pass. | required |
| repo-in-use | Read the archived flag, "last push to any branch," latest release date, and star count under Repo facts. | Pass only if archived is false and at least one of these is true: the last push was within 180 days, the latest release was within 365 days, or the repository has at least 100 stars. Measure dates against the bundle capture date in eval mode or today's date in live mode. | required |
| scope-fits | Read the issue body and Comments section for the requested change, affected component, expected behavior, design discussion, and statements about core internals. | Pass if the issue requests one bug fix, documentation or test change, or feature with a named component or one testable expected outcome. Fail if it is explicitly an umbrella or tracking issue, a pure usage or support question, an unresolved design discussion without a maintainer decision, or if a maintainer says the work requires changes to core internals. Missing reproduction steps alone does not fail this check. | required |
| unclaimed | Read "this issue: assignees" and "linked PRs" under Repo facts. Read the Comments section for referenced PRs and claim statements such as "I'll take this," "can I work on this," or "working on this." | Pass if there is no assignee, no open linked or comment-referenced PR, and no explicit claim made within the last 30 days. An open PR or any assignee fails the check. A claim older than 30 days passes only when there is no open associated PR and no later comment showing continued work. | required |
| ai-contribution-policy | Read the "contribution policy" line under Repo facts for CONTRIBUTING.md, AI policy files, contributor documentation, and PR or issue template requirements. | Fail only if the repository explicitly bans AI-generated or AI-assisted contributions. Pass if the policy is silent or absent, or if it permits AI use with conditions such as disclosure, personal understanding, testing, or human review. | required |
| newcomer-signal | Read the issue labels, label event lines, issue body, and Comments section for a good-first-issue label, an acceptance-criteria checklist, or a testable expected result. | Pass if the issue has a good-first-issue label or contains an acceptance-criteria checklist or testable expected result. Otherwise mark fail. | preferred |

## Verdict rule

Accept only if every required check passes. A fail or unclear grade on any required check produces a reject verdict. Preferred checks never change the verdict; they are used only to rank accepted issues. A fail or unclear grade on a preferred check does not affect the verdict.
